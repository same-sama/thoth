THOTH

接入自己部署的服务

Thoth 认 OpenAI 的接口格式。你自己部署的语音、识图、生图服务，只要兼容下面对应的接口，就能接进来。每个入口都有「测试一下」，接不通时会告诉你卡在地址、Key 还是接口格式。

地址

  • 局域网里的服务可以用 http://，比如 http://192.168.1.10:8000/v1。第一次连时 iOS 会问是否允许 Thoth 访问本地网络，选允许。
  • 放在公网上的服务必须用 https://，证书要是正规签发的（自签名不行）。没有 https 的话，可以用 Caddy 或 Cloudflare Tunnel 免费加一层。

语音（TTS）

入口：设置 › 模型与服务 › 语音服务 › 添加 TTS 服务

POST {地址}/v1/audio/speech
{"model": "...", "input": "要读的文字", "voice": "...", "response_format": "wav", "speed": 1}
  • 必须返回 WAV（Content-Type: audio/wav），只能返回 mp3 的服务接不了。
  • 鉴权三选一：Authorization: Bearer <Key>、X-API-Key: <Key>、不鉴权。
  • 地址可以填服务根地址、到 /v1 为止，或者完整的 /v1/audio/speech。
  • 模型和音色填服务认的 ID，多个用逗号隔开，第一个是默认值。

识图

入口：设置 › 模型与服务 › 图像识别 › 子智能体接入

  1. 先在「设置 › 模型与服务 › 模型服务 › 添加 › 自定义兼容服务」里接入你的服务，Base URL 填到 /v1（比如 Ollama：http://电脑IP:11434/v1）。不需要 Key 的服务，Key 随便填一个（比如 none）。
  2. 回到子智能体接入，选这个服务和 Key，模型填一个支持图片输入的模型（比如 qwen2.5vl、llava）。
  3. 点「测试一下」：会发一张纯红色小图，模型说得出颜色就算通了。

接口：POST {Base URL}/chat/completions，图片按 OpenAI 的 image_url（base64 data URL）发送。

生图

入口：朋友设置 › 生成图片 › 独立能力模型（同样先在模型服务里接入）

POST {Base URL}/images/generations
{"model": "...", "prompt": "...", "n": 1, "size": "1024x1024"}
→ {"data": [{"b64_json": "..."}]} 或 {"data": [{"url": "..."}]}

size 只会是 1024x1024、1536x1024、1024x1536 之一。「测试一下」会真的画一张小图，按服务计费。

卡在地址：http 只能连局域网公网服务换成 https

自分で立てたサービスをつなぐ

Thoth は OpenAI の API 形式に対応しています。自分で立てた音声・画像認識・画像生成サービスも、下の API と互換なら接続できます。各画面の「テストする」で、つながらないときにアドレス・キー・API 形式のどこで止まっているかが分かります。

アドレス

  • LAN 内のサービスは http:// でも使えます（例：http://192.168.1.10:8000/v1）。初回に iOS がローカルネットワークへのアクセスを確認するので、許可してください。
  • インターネット上のサービスは https:// が必要で、正式に発行された証明書が必要です（自己署名は不可）。Caddy や Cloudflare Tunnel で無料で https にできます。

音声（TTS）

設定 › モデルとサービス › 音声サービス › TTS サービスを追加

POST {アドレス}/v1/audio/speech
{"model": "...", "input": "読み上げるテキスト", "voice": "...", "response_format": "wav", "speed": 1}
  • WAV を返す必要があります（Content-Type: audio/wav）。mp3 しか返せないサービスは使えません。
  • 認証：Authorization: Bearer <Key>、X-API-Key: <Key>、認証なし のいずれか。
  • アドレスはルート、/v1 まで、または完全な /v1/audio/speech のどれでも構いません。
  • モデルと音声はサービスの ID をカンマ区切りで。先頭が既定値です。

画像認識

設定 › モデルとサービス › 画像認識 › サブエージェント

  1. まず「設定 › モデルとサービス › モデルサービス › 追加 › カスタム互換サービス」でサービスを追加します。Base URL は /v1 まで（Ollama なら http://PCのIP:11434/v1）。キー不要のサービスでも、キー欄には何か（例：none）を入れてください。
  2. サブエージェントでそのサービスとキーを選び、画像入力に対応したモデル（例：qwen2.5vl、llava）を入力します。
  3. 「テストする」で真っ赤な小さい画像を送り、色を答えられれば OK です。

API：POST {Base URL}/chat/completions。画像は OpenAI の image_url（base64 data URL）形式で送ります。

画像生成

友だちの設定 › 画像生成 › 専用機能モデル（先にモデルサービスへ追加）

POST {Base URL}/images/generations
{"model": "...", "prompt": "...", "n": 1, "size": "1024x1024"}
→ {"data": [{"b64_json": "..."}]} または {"data": [{"url": "..."}]}

size は 1024x1024、1536x1024、1024x1536 のいずれかです。「テストする」は実際に小さな画像を 1 枚生成し、料金がかかります。

Connecting a Self-Hosted Service

Thoth speaks the OpenAI API format. A voice, image-recognition or image-generation service you host yourself works if it's compatible with the endpoints below. Each settings page has a Test It button that tells you whether a failure is at the address, the key or the API format.

Addresses

  • Services on your local network can use http://, e.g. http://192.168.1.10:8000/v1. The first time, iOS asks whether Thoth may access your local network; allow it.
  • Services on the internet need https:// with a properly issued certificate (self-signed won't work). Caddy or Cloudflare Tunnel can add https for free.

Voice (TTS)

Settings › Models & Services › Voice Services › Add TTS Service

POST {address}/v1/audio/speech
{"model": "...", "input": "text to read", "voice": "...", "response_format": "wav", "speed": 1}
  • Must return WAV (Content-Type: audio/wav). Services that only return mp3 won't work.
  • Authentication: Authorization: Bearer <key>, X-API-Key: <key>, or none.
  • The address may be the service root, end at /v1, or be the full /v1/audio/speech.
  • Enter model and voice IDs the service recognizes, comma-separated; the first is the default.

Image recognition

Settings › Models & Services › Image Recognition › Sub-agent

  1. First add your service under Settings › Models & Services › Model Services › Add › Custom compatible service, with the Base URL ending at /v1 (for Ollama: http://your-computer-ip:11434/v1). If it needs no key, enter anything as the key (e.g. none).
  2. In Sub-agent, choose that service and key, and enter a model that accepts images (e.g. qwen2.5vl, llava).
  3. Tap Test It: it sends a small solid-red image; if the model names the color, it works.

Endpoint: POST {Base URL}/chat/completions, with images sent as OpenAI image_url base64 data URLs.

Image generation

Friend Settings › Image Generation › Dedicated Capability Model (add the service under Model Services first)

POST {Base URL}/images/generations
{"model": "...", "prompt": "...", "n": 1, "size": "1024x1024"}
→ {"data": [{"b64_json": "..."}]} or {"data": [{"url": "..."}]}

size is always one of 1024x1024, 1536x1024 or 1024x1536. Test It really generates one small image and is billed by the service.
